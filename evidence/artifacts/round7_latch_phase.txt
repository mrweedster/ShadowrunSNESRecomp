== 1. The same guest instruction, both tiers ==

  frame   ctrl_entry  ctrl_latch   seed_entry  seed_latch   d_entry  d_latch  d_h  d_latch/4

   1836    656716844    656716908    656716844    656716932       +0      +24   +6    +6.0

  in-body charge (latch - entry): f1832 ctrl +64 / seed +88, f1833 ctrl +64 / seed +88, f1834 ctrl +64 / seed +88, f1835 ctrl +64 / seed +88, f1836 ctrl +64 / seed +88

  The +24 is the LDA $2137's own bus transfers.  The compiled body
  charges its three fetch cycles before the read and the fourth
  (the paced data read) inside cpu_read8_paced, and ReadRegOpenBus
  advances the beam to cpu->master_cycles: 4 x 6 = 24 master clocks.
  The interpreter commits s_interp_bus_master only after
  interp816_runOpcode returns, so at the same read it sits 24 clocks
  earlier.  Every row has d_latch == d_entry + 24.

  The rows do not share one d_latch: the entry clocks themselves
  differ by up to 56 master clocks, because the frame reaches the
  body at a different point on the two tiers.  That is the phase
  term the read convention cannot remove.

== 2. The latch follows the sample time exactly ==

  d_h is always d_latch/4: the H counter advances one count per 4
  master clocks, so the latched H is a direct function of sync=.  A
  difference in d_latch is therefore a difference in the value the
  game reads, not a bookkeeping residual: f1832 reads H=98 (ctrl)
  against H=91 (seed), a 7-dot split at the same guest instruction.

== 3. The gate, with and without a read-time fix ==

  default                : first state f1830, 305 of 4575 frames, 895 bytes
  SNESRECOMP_LATCH_SYNC=1: first state f1830, 1333 of 4575 frames, 3031 bytes
  crc32_wram first diff  : f1828 0xB615CF19 vs 0xC912779D  (same in both parity runs)

  LATCH_SYNC advances every interpreted latch by its pending master,
  so it removes the 24-clock convention term: d_latch becomes
  d_entry (+24 -> 0 on f1835/f1836, +80 -> +56 on f1834, but
  -28 -> -52 and -16 -> -40 on f1832/f1833).  The gate's first state
  divergence does not move (f1830) and the frame count grows
  305 -> 1333 (895 -> 3031 bytes).  Removing the convention term is
  not enough: the entry-phase term dominates the early frames, and
  the divergence is already set before this body runs.

== 4. What this settles ==

  'Price the counter read' is necessary but not sufficient.  The
  compiled body does latch 24 master clocks later than the
  interpreter at an equal entry clock, and that is a real, fixable
  convention difference.  But the two tiers also enter the body at
  clocks that differ by up to 56 master clocks, so the latched H
  differs by a variable number of dots.  A framework change that
  only adjusts the read cannot restore the pair; the guest timeline
  up to the read has to be path-invariant first.  That is the
  direction the upstream seam report (§5 item 3) names, and it is
  larger than this round's probe.

  The earliest non-label state byte (f1830, $7E00126) precedes the
  first $80C530 entry on both tiers (f1832), so this latch is not
  that byte's cause; it is the mechanism behind the DP $00/$01
  cluster that opens at f1832, which is what round 6's write trace
  named.
